# Platform lifecycle adapters contain request members

The runtime reports cleanup only for processes contained by its platform Lifecycle Adapter, not every descendant ever created. Windows uses a per-request Job Object implemented through `koffi`: it does not enable a breakaway limit, configures `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` for final-handle crash cleanup, and uses forced `taskkill /T /F` only as an unconfirmed fallback. `child.kill()` is abrupt on Windows and is not a graceful tree-stop request. The fallback retains its observed numeric exit status and output only as diagnostics—local `128` observations are not a portable contract, and its parent/child traversal snapshot can miss reparented work. Immediate Job assignment narrows but cannot eliminate the post-spawn/pre-assignment race, in which a detached child can escape; a different pre-existing Job can also reject assignment. Unix guarantees only the runner-created process group, so a `setsid()` or new process group escapes. `treeCleaned` is true only after independent bounded confirmation that no contained member remains; it is false with diagnostics when containment or confirmation fails, and null after natural completion. Windows `.cmd` and `.bat` Platform Wrappers do not provide arbitrary literal arguments: cmd.exe expands and can split `%PATH%`, `!VAR!` depends on delayed expansion, and `&|<>^` is parser syntax that can fail before the wrapper. The runtime rejects those characters for wrappers; accepted wrapper arguments remain a narrowed capability, unlike native executable literal argv.
