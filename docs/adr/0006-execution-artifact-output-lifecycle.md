# Execution Artifacts are immutable completed-output records

`CommandRuntime` owns the Artifact/output state machine behind its intended inspect, execute, Output Page read, and close interface; MCP is only the future `system_output` adapter. For each Execution Request, each stream always feeds byte accounting and bounded Inline Output (head/tail UTF-8 diagnostic projection). An Artifact is separately either `not-requested` (`never`), `spooling`, `discarded` (`on-truncation` with neither stream truncated), `publishing`, `published`, or `unavailable`. `spooling` begins at process start whenever policy might retain an Artifact, so `on-truncation` can publish complete streams. `not-requested`, `published`, `discarded`, and `unavailable` are terminal; temporary spool state has no identity and is never readable.

After process termination and stream closure, a complete spool either moves atomically through `publishing` to `published`, or is deleted and reported `unavailable`. Per-stream limits, spool write errors, metadata/version errors, lock/quota failures, and publication failures all take the latter path: no partial Artifact or identity is exposed, while the Execution Result and Inline Output remain authoritative for the process outcome. Before publication, cleanup may remove expired Artifacts and then least-recently-published Artifacts to satisfy the fixed total quota. Reads never extend the publication-based retention age. Expired, evicted, absent, and failed Artifact identities are indistinguishable as `ARTIFACT_NOT_FOUND`; concurrent runtimes coordinate cache cleanup and publication with the cache lock and atomic rename.

A published Artifact is immutable and contains complete raw stdout and stderr plus non-secret metadata. `readOutput(id, stream, offset, limit, encoding)` is accepted only while the runtime is open and the Artifact is published: offsets and limits are byte-based, the page reports actual bytes, `nextOffset`, and `eof`; `base64` is lossless and UTF-8 declares lossy decoding when applicable. An offset at the stream length returns an empty EOF page; an offset beyond it or an invalid limit/stream is a request error. Runtime Closing rejects every new execution and Output Page read with `RUNTIME_CLOSING`, rather than exposing a raced partial spool.

Close cancels active Execution Requests and allows any request that reaches normal stream closure within the shared shutdown deadline to take its normal discard-or-publish transition; it then deletes all remaining spools and releases locks. Published Artifacts remain subject to normal retention. On process crash no spool is published; startup stale-spool recovery deletes abandoned temporary state before admitting work. Artifact persistence, cleanup, or recovery failure never changes a successfully started process's Execution Terminal State, although its Artifact Status records unavailable persistence. Windows `.cmd` and `.bat` Platform Wrappers remain direct-program registrations, but cmd.exe reparses their arguments, so literal Argument Vector semantics are guaranteed for native executables only.
